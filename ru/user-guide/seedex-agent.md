# seedex-agent

Эта страница описывает команду `sdx` на сервере.

## Команда `sdx`

`sdx` на сервере построен вокруг трёх сервисов — `vpn`, `proxy` и `link` — и следует тому же шаблону, что на роутере:

* `sdx` показывает статус сервера.
* `sdx <service>` показывает статус одного сервиса.
* `sdx <service> <action>` выполняет одно действие над одним сервисом.
* `sdx <action>` выполняет то же действие над каждым сервисом, у которого оно есть.
* `sdx <service> help` перечисляет действия сервиса.

Каждую команду с этой страницы можно запускать и с роутера: `sdx link <name> ...`.

### Действия каждого сервиса

* `sdx <service> start`, `stop` и `restart` управляют сервисом. Без сервиса `sdx start` запускает все три сервиса.

### Действия сервера в целом

* `sdx firewall setup` настраивает фаервол под используемые порты, `sdx firewall status` показывает фаервол.
* `sdx version` печатает версию установленного агента.

## VPN

Сервис VPN — сервер AmneziaWG. Параметры обфускации генерируются для установки, поэтому на проводе никакие два сервера не выглядят одинаково. Каждый клиент получает тот же набор.

* `sdx vpn` показывает, работает ли сервис, интерфейс, порт и клиентов.
* `sdx vpn add [<name>]` добавляет клиента. Команда генерирует ключи и preshared key, назначает следующий свободный адрес, добавляет peer на работающий интерфейс без его перезапуска и записывает клиентский конфиг. Без имени клиенты нумеруются.
* `sdx vpn remove <name>` отзывает клиента. `sdx vpn remove --all` отзывает каждого клиента.
* `sdx vpn config` показывает endpoint сервера, публичный ключ и параметры обфускации.
* `sdx vpn export [<name>] [-o <dir>]` записывает клиентские конфиги, один или все, в файлы `.conf`, которые `sdx import` на роутере принимает. С линком это не нужно: роутер забирает конфиги сам.
* `sdx vpn rotate` генерирует ключи сервера и параметры обфускации заново. Каждый существующий клиент перестаёт работать. Добавьте клиентов заново.

## Proxy

Сервис proxy — сервер sing-box с протоколами, которые выбираете вы: `vless` (Reality), `trojan`, `shadowsocks`, `shadowtls`, `vmess`, `hysteria2`, `tuic` и `anytls`.

* `sdx proxy` показывает, работает ли сервис, и перечисляет протоколы с их портами.
* `sdx proxy add <protocol> <port>` добавляет протокол на порту. Команда генерирует учётные данные, открывает порт и перезапускает sing-box.
* `sdx proxy remove <protocol>` удаляет протокол и закрывает его порт.
* `sdx proxy config` показывает учётные данные для подключения по каждому протоколу.
* `sdx proxy export [<protocol>] [-o <dir>]` записывает клиентские конфиги, один протокол или все, в файлы `.json`, которые `sdx import` на роутере принимает.
* `sdx proxy rotate [<protocol>]` генерирует учётные данные заново для одного протокола или для всех. Порты не меняются.

## Link

Сервис link — API, с которым соединяется роутер. Роутер забирает через него конфиги и запускает через него `sdx` на сервере.

* `sdx link` показывает, работает ли сервис, порт, отпечаток сертификата и соединённые роутеры.
* `sdx link add <router>` соединяет роутер. Команда выдаёт токен и печатает токен, отпечаток и точную команду `sdx link add` для роутера. Токен показывается один раз.
* `sdx link remove <router>` отсоединяет роутер. Его токен перестаёт работать.
* `sdx link rotate` генерирует сертификат API заново. Каждый роутер должен соединиться заново с полученным отпечатком.
